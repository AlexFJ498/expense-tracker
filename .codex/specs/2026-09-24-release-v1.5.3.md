# v1.5.3 release updater metadata

## Intent
- Goal: publish the Kutxabank import fix as v1.5.3 with a complete GitHub Release updater manifest.
- User value: installers and in-app updates work for supported desktop platforms.
- Non-goals: change import behavior, add architectures, or alter signing credentials.

## Slice
- Frontend, Tauri commands/API, workbook, analytics: unchanged.
- Release workflow: collect installers, update bundles, and signatures for Windows x64, Linux x64, and macOS arm64; generate one static `latest.json` only when all three are valid.
- Version metadata: synchronize package, Cargo, and Tauri versions; derive displayed app versions from package metadata.
- Tests: exercise manifest generation using synthetic artifacts and missing-file cases; run the existing app test/build matrix.

## Context To Read
- Must read: `.github/workflows/release.yml`, `src-tauri/tauri.conf.json`, npm/Cargo version metadata, Tauri updater static JSON documentation.
- Do not read: signing private keys, real workbooks, bank exports, generated build folders.

## Contract
- `latest.json` must contain `version: 1.5.3` and a `platforms` object keyed by `windows-x86_64`, `linux-x86_64`, and `darwin-aarch64`.
- Each platform must have an HTTPS release asset URL and the full content of its matching `.sig` file.
- A missing artifact, signature, duplicate candidate, or mismatched version must fail before release publication.
- The app updater endpoint remains `https://github.com/AlexFJ498/expense-tracker/releases/latest/download/latest.json`.
- Pull requests run secret-free Node manifest tests and frontend tests/build; no PR-controlled job receives signing secrets.
- A manual workflow dispatch on `main` runs signed platform builds and validates the combined manifest before tagging. Signed jobs must not run from a manually selected non-`main` ref.
- Only a `v*` tag push may enter the release publication job.

## Tests First
- RED: generator test fails when `latest.json` generation is absent.
- GREEN: generator test passes for all three synthetic platforms and rejects incomplete input.
- Manual: inspect GitHub release assets and the published JSON after the tag-triggered workflow completes.
- CI preflight: confirm secret-free PR checks pass, then run and inspect signed Windows, Linux, macOS, and manifest validation from protected `main` after merge and before tag.

## Acceptance
- `npm test`, `npm run build`, `cargo test`, `npm audit`, release-sensitive Tauri build, and generator tests pass or any environmental limitation is reported before tagging.
- v1.5.3 tag targets the reviewed merge commit; the GitHub Release includes installers and a parseable cross-platform updater manifest.

## Decision Log
- 2026-09-24: Keep the existing tag-triggered release pipeline and add fail-closed updater manifest generation rather than replacing the entire build action.
- 2026-09-25: Replace the signed same-repository PR preflight: a PR branch controls code executed by its workflow, so fork filtering does not protect signing secrets. Run secret-free PR checks and use a manual `main` dispatch for signed preflight after merge; keep publication tag-only.
